# spaceLog 문제 정의 가설 (팀 회의용 초안)

- 작성: 2026-11-24 · 발표: 2026-12-02 · 팀 4명
- 상태: **가설**. 리서치(인터뷰 또는 설문)로 확인하기 전이다.
- 출발점: 기획자 한 명(팀원)의 경험. 아래 내용은 이 경험을 가설로 정리한 것이다.

---

## 1. 문제 가설

| 항목 | 내용 |
|---|---|
| 대상 | 레퍼런스·자료를 꾸준히 모으는 기획자, 마케터, 디자이너. 대부분 ChatGPT나 Claude를 이미 쓴다 |
| 상황 | 새 작업(기획서, 캠페인, 시안)을 하다가 예전에 저장해 둔 자료가 필요해진다 |
| 문제 | ① 무엇을 적었는지 기억나지 않는다 ② 같은 도구 안에서도 어디(어느 페이지·폴더)에 뒀는지 기억나지 않는다 ③ 너무 많이 쌓여 훑어볼 수 없다 |
| 지금의 대안 | 노션, 메모장, 브라우저 북마크, 스크린샷 폴더, 카톡 "나에게 보내기" 등 *(추정, 리서치로 확인)* |
| 대안의 한계 | 노션처럼 기능·설정이 많은 도구는 배워야 쓸 수 있다. 가볍게 남기려는 사람에게는 부담이다. 쌓인 뒤에는 다시 찾기가 어렵다 |

**한 문장으로:** 가볍게 모아 두고 싶을 뿐인데, 기존 도구는 쓰기 전엔 배워야 하고 쌓인 뒤엔 다시 찾을 수 없다.

## 2. spaceLog의 답 (가설)

**간편하게 저장하고, 편하게 찾아 꺼내 쓴다.**

| 단계 | 방법 |
|---|---|
| 저장 | 설치형 바로 캡처·링크 등록, 평소 쓰는 AI(Claude·GPT)에서 MCP로 저장, 웹에서 끌어다 놓기 |
| 다시 찾기 | AI를 쓰는 사람은 MCP로, 안 쓰는 사람은 spaceLog 챗봇으로. 북마크, 우주 화면(행성·기간) |
| 다시 떠올리기 | 리마인드 *(방식 미정)* |
| 새 영감 | 기록끼리 연결하기 *(방식 미정, "connecting the dots")* |
| 콘셉트 | 우주. 기록 서비스가 많은 만큼 사람들이 좋아할 특별함으로 가져간다 |

- 구조: 로컬 앱에서 **서버 + DB로 옮긴다**. **각자 자기 기록만 보는 개인 계정**이다(팀 공유 없음).
- 아직 정의되지 않은 것: 그룹화(행성과의 차이), 리마인드 방식, 기록 연결 방식.

## 3. 경쟁 서비스

| | mymind | Raindrop.io | 노션 | spaceLog (계획) |
|---|---|---|---|---|
| 정체성 | 정리 없는 개인 영감 저장소 | 북마크 관리자 | 다목적 작업 공간 | 우주 콘셉트 아카이브 |
| 정리 방식 | 자동(AI 태그) | 수동(컬렉션·태그) | 수동(페이지 계층·DB) | 행성 선택 + 그룹화(미정) |
| 다시 찾기 | 색·글자·이미지 검색 | 검색(전문 검색은 유료) | 검색, 노션 AI | 챗봇, MCP, 우주 화면, 북마크 |
| 리마인드 | Serendipity(잊은 것 다시 보여 주기) | 확인 못 함 | 없음 | 계획 중 |
| 기록 연결 | 양방향 링크, 그래프 예정 | 없음 | 링크·관계형 DB | 고민 중 |
| AI 채팅·MCP | 없음 | 유료에 AI 도우미 | 노션 AI, 공식 MCP | 챗봇 + MCP |
| 협업 | 일부러 없음 | 컬렉션 공유 | 강함 | 없음(개인 계정) |
| 배우는 부담 | 낮음 | 중간 | 높음 | 낮게 |
| 한국어 | 언급 없음 | - | 지원 | 지원 |

**가장 가까운 경쟁자는 mymind다.** "모든 걸 기억하고, 아무것도 정리하지 않는다"를 내세우고, 디자이너·마케터를 겨냥하며, 미감과 프라이버시로 팬을 만들었다. 발표에서 "mymind와 뭐가 다르냐"는 질문은 반드시 나온다.

**차별점 후보 (한 문장 초안)**
> 평소 쓰는 AI 안에서 그대로 저장하고 꺼내 쓰고, 쌓인 기록이 별자리처럼 이어져 새 영감이 되는, 한국어 아카이브.

- 근거: 조사한 서비스 중 "AI 대화 안에서 저장·꺼내기"는 없었다(노션 MCP는 있지만 배워야 하는 노션 위에 있다).
- 제안: 기록 연결을 **별자리**로 보여 주면 우주 콘셉트가 꾸밈이 아니라 기능이 된다. *(제안, 팀 결정 필요)*

## 4. 확인해야 할 가정 (위험한 순서)

| # | 가정 | 틀리면 | 위험도 |
|---|---|---|---|
| A1 | 저장한 자료를 다시 못 찾는 일이 자주 있고, 그때 손해가 크다 | 문제 자체가 약해진다("다시 검색하면 그만") | 높음 |
| A2 | 못 찾는 원인은 "기억이 안 나서"(무엇·어디)다. 애초에 저장을 안 한 게 아니다 | 해결책이 "저장을 쉽게" 쪽으로만 옮겨 간다 | 높음 |
| A3 | 대상은 AI 챗을 자주 쓰고, 그 안에서 저장·불러오기를 원한다 | MCP라는 핵심 차별점의 근거가 약해진다 | 높음 |
| A4 | 업무 자료(고객사 자료 포함)를 서버와 AI에 맡기는 데 큰 거부감이 없다 | 서버 전환과 챗봇이 신뢰 문제에 막힌다 | 중간 |
| A5 | 기존 도구가 복잡해서 기록을 포기하거나 대충 한 경험이 있다 | "단순함" 차별점이 약해진다 | 중간 |
| A6 | 잊은 기록을 다시 보여 주거나 이어 주면 실제로 도움이 된다 | 리마인드·연결의 근거가 약해진다 | 중간 |
| A7 | 우주 화면이 찾기나 다시 보기를 더 즐겁게 만든다 | 핵심 화면이 장식이 된다 | 낮음(시연으로 보여 줄 수 있음) |

## 5. 리서치 방법 고르기 (회의에서 결정)

| | 인터뷰 | 설문 |
|---|---|---|
| 잘하는 것 | 몰랐던 문제와 이유를 발견한다(A2, A6) | 이미 아는 선택지가 얼마나 흔한지 숫자로 보여 준다(A1, A3, A4) |
| 못하는 것 | 숫자로 보여 주기 어렵다 | 선택지 밖의 문제를 못 찾는다 |
| 필요한 것 | 5~8명, 1인 30분 | 많을수록 좋다(100명 이상 권장), 1인 5~6분 |
| 발표에 남는 것 | 인용문, 대표 장면 | 그래프, 비율 |

**권고:** 시간이 없다면 **설문**으로 가고, 설문 끝에서 인터뷰 지원자를 받아 2~3명과 15분 통화를 더한다.

**질문을 만든 원칙**
- 미래·가정("쓰시겠어요?")이 아니라 **가장 최근의 실제 행동**을 묻는다.
- 유도하지 않는다. "불편하셨죠?"가 아니라 "그때 어떠셨어요?"
- 우리 가설을 선택지로만 주지 않는다. 주관식과 "기타(직접 입력)"를 둔다.
- 주관식 경험 질문을 앞에 둔다. 선택지를 먼저 보면 그 표현이 답에 섞인다.
- AI 이야기는 늦게 꺼낸다. 응답자가 먼저 AI를 말하는지가 증거가 된다.
- 지인 30명 안팎이면 "통계적으로 그렇다"가 아니라 "경향이 보였다"로만 말한다.

**시작 안내문 (예시)**
> 업무 자료를 저장하고 다시 찾는 경험에 대한 설문입니다. 5분 정도 걸리고, 정답은 없습니다. 답변은 수업 프로젝트 발표에만 쓰고, 개인을 알아볼 수 있는 정보는 공개하지 않습니다.

### 5-2. 인터뷰 가이드 (30분)

**진행 방식**
- 2명이 한 조로 들어간다. 한 명은 묻고, 한 명은 받아 적는다.
- 녹음은 동의를 받고 한다. 받아 적을 때는 해석하지 말고 **들은 말 그대로** 적는다.
- 원칙: 유도하지 않기("불편하셨죠?" ✕ → "그때 어떠셨어요?" ○), 침묵을 견디기, 파고들기("왜요?", "그다음엔요?", "예를 들면요?").

|---|---|---|---|---|
| 시작 | 3분 | "제품을 평가받는 자리가 아니라, 자료를 모으고 찾는 경험을 듣는 자리예요. 정답은 없어요. 녹음해도 될까요?" | | |

## 6. 회의에서 정할 것

1. 리서치 방식: 설문만 / 설문 + 짧은 통화 / 인터뷰 — 누가, 언제까지
2. "왜 mymind가 아니라 spaceLog인가" 한 문장 확정
3. **하지 않을 것** 목록 (단순함을 지키는 장치). 예: 폴더 계층은 만들지 않는다, 저장할 때 행성 고르기를 강제하지 않는다
4. 기능 5개 범위: 12/2까지 완성할 것 / 시연용으로만 보여 줄 것 / 다음으로 미룰 것
5. 그룹화, 리마인드, 기록 연결의 정의 (리서치 결과를 보고 확정해도 된다)
6. 발표 대표 장면 하나: 예) 기획자가 GPT에서 저장 → 일주일 뒤 리마인드 → 이어진 기록에서 영감 → 챗봇이나 MCP로 꺼내기
7. 성공 기준 하나: 예) "찾는 데 걸리는 시간", "못 찾은 경험 비율"
