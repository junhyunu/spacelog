# 별의 글칸을 "메모" 하나로 합치기 — 설계

2026-11-25 · 작은 변경

## 왜

별 띄우기 창 맨 위 입력칸(본문)과 상세 패널의 메모칸이 서로 다른 칸이라 헷갈린다. 별 하나에 글이 두 군데 생기고, 본문은 저장한 뒤 고칠 수 없다. 사용자에게 보이는 글칸을 **"메모" 하나**로 통일한다.

## 목표 · 하지 않을 것

- 목표: 별 띄우기 창과 상세 패널 모두 "메모" 칸 하나만 보인다. 상세 패널에서 바로 고칠 수 있다.
- 목표: 기존 별도 같은 모양이 된다(점선 본문 상자가 어디에도 남지 않는다).
- 하지 않을 것: DB의 `memo` 열 삭제, 첨부 · 제목 · 행성 동작 변경.
- 실패로 보는 것: 기존 별의 본문이나 메모 글이 하나라도 사라지는 것.

## 접근 (고른 것: A)

| | A. 본문을 남김 (**선택**) | B. 메모를 남김 |
|---|---|---|
| 저장 | 별 띄우기는 지금처럼 `body`로 보냄 | 별 띄우기가 `memo`로 보내게 고침 |
| 고칠 곳 | 상세 패널 + 본문 고치기 API | 저장 · 빈 제목 규칙 · "종류" 표시(서버와 웹) |

A는 만드는 쪽 코드를 그대로 두고 상세 패널만 바꾸면 돼서 고칠 곳이 적다. 화면에서 보이는 이름만 "메모"다. B는 결과는 같지만 고칠 곳이 더 많다.

## 정한 것

### 데이터

- 별의 글은 `body` 하나다. `memo` 열은 남겨 두지만 더 이상 쓰지 않는다.
- **이전(마이그레이션, 한 번):** `memo`가 비어 있지 않은 별은 `body = body가 있으면 body + "\n\n" + memo, 없으면 memo`, `memo = ''`. 검색어(`search_text`)는 다시 만들고, 바뀐 별은 챗봇 색인을 다시 하도록 표시한다. DB 버전을 하나 올린다(`server/db.js`의 migrateTo 방식).

### 서버

- `PATCH /api/stars/:id`가 `body`를 받는다. 지금 `memo`처럼 문자열이어야 하고 2만 자(코드 포인트) 이하다. 비우면 `null`로 저장한다.
- 고치면 `search_text`를 다시 만들고 `ragSync.markStars([id], 'patch')`를 부른다(지금 메모와 같은 흐름).
- `PATCH`의 `memo`는 계속 받는다(옛 클라이언트용). 새 웹은 보내지 않는다.
- 만들 때(`POST`) 본문 한도도 2만 자로 맞춘다.

### 별 띄우기 창 (`web/index.html` `#save`, `saveModal.js`, `save.css`)

- 순서: [파일 첨부][링크 붙이기] · 첨부 칩 → 제목 → **메모** → 행성.
- 메모칸: 라벨 "메모", placeholder **"이 별에 남길 말"**.
- 제목 칸의 빈칸 안내: "비워 두면 메모 첫 줄을 써요".
- 창을 열면 커서는 메모칸에 둔다.
- 끌어다 놓거나 붙여넣은 글은 지금처럼 이 칸에 들어간다.

### 상세 패널 (`detail.js`, `detailLogic.js`, `detail.css`)

- 점선 본문 상자를 없앤다. "메모" 칸 하나에 `body`를 보여 주고, 지금 메모처럼 입력을 멈추면 자동 저장한다(`PATCH { body }`).
- placeholder: "이 별에 남길 말".
- "종류"의 "글"은 지금처럼 `body`가 있으면 붙는다.

### 메모칸 크기 · 글자 수 (두 곳 같게)

- 최소 3줄, 최대 화면 높이의 40%. 넘으면 칸 안에서 스크롤한다.
- 쓰는 만큼 자동으로 늘어난다. 손으로 끄는 손잡이(`resize`)는 없앤다.
- 2만 자까지. 1만 8천 자부터 칸 아래에 "18,200 / 20,000"을 보이고, 넘으면 빨간색으로 바꾸고 저장 · 별 띄우기를 막는다. 붙여넣은 글을 몰래 자르지 않는다(`maxlength` 쓰지 않음).

## 만드는 사람에게 맡기는 것

- 이전 때 합친 본문이 2만 자를 넘는 별(드묾): 그대로 두고 보여 준다. 고칠 때만 한도를 적용한다.
- 상세 패널 자동 저장의 `keepalive` 크기 판단(`fitsKeepalive`)은 지금 메모 로직을 그대로 쓴다.
- `DESIGN.md`와 1차 스펙의 "글 칸" 설명을 바뀐 내용에 맞게 고친다.
- 테스트: 이전(합치기 · 빈 메모 · 본문 없음), `PATCH body`(한도 · 비우기 · 검색어 · 색인 표시), 상세 패널 저장.
