# spaceLog 2차 · 기록 챗봇 설계

- 날짜: 2026-11-13
- 기준: [1차 설계](2026-11-12-spacelog-phase1-design.md)(6-8 ~ 6-10 포함), [DESIGN.md](../../../DESIGN.md), 수업 자료 `D22_1112.html`(LangChain + RAG)
- 표기: **(결정)** 사용자가 정한 것, **(내 판단)** 설계자가 정한 기본값

## 1. 무엇을, 왜

spaceLog에 쌓인 기록(별의 제목 · 글 · 메모 · 링크 제목 · 첨부 파일 내용)을 하나의 검색 가능한 자료로 만들고, 챗봇으로 **찾고 · 묻고 · 요약**한다(결정). 수업에서 배운 RAG 방식(자르기 → 숫자로 바꾸기 → 비슷한 조각 찾기 → 조각 보고 답하기, 출처 표시, 없으면 모른다고 하기)을 **파이썬 LangChain으로** 그대로 쓴다(결정: A안).

## 2. 목표 · 하지 않는 것 · 실패 기준

**목표**
1. 별을 저장 · 수정 · 삭제하면 챗봇이 읽는 색인이 저절로 맞춰진다.
2. "지난주 회의록 PDF 어디 있어?" 같은 **찾기**, "MCP가 뭐라고 적어 뒀더라?" 같은 **묻기**, "이 행성 이번 주 내용 정리해 줘" 같은 **요약**이 된다.
3. 답에는 근거가 된 별이 **출처 카드**로 붙고, 누르면 그 별로 날아가 상세가 열린다.
4. 기록에 없으면 "기록에서 찾지 못했어요"라고 말하고 지어내지 않는다.
5. 대화는 저장되고 나중에 이어 볼 수 있다(결정).

**하지 않는 것 (2차 1단계)**
- 챗봇이 기록을 만들거나 옮기거나 지우는 일(결정). 대신 답마다 "별로 저장" 버튼.
- 이미지 속 글자, 스캔 PDF, hwp 본문, 링크 페이지 본문 읽기(결정: 이름 · 메모 · 제목만).
- 대화 이름 바꾸기 · 검색 · 고정 · 내보내기(결정).
- Docker, 인터넷 배포, 로그인, 여러 사용자(결정: 나중에 한 묶음으로).

**이러면 실패**
- 출처 카드가 실제로 근거가 아닌 별을 가리킨다(출처를 AI가 지어낸다).
- 기록에 없는 것을 그럴듯하게 지어낸다.
- 챗봇을 켜지 않았는데 기록이 OpenAI로 나간다. 또는 "빼 둔 행성"의 내용이 나간다.
- 파이썬 쪽이 없거나 꺼져 있을 때 spaceLog의 나머지 기능이 함께 멈춘다.

## 3. 구성

```
브라우저 ──(127.0.0.1:4747)── Node 서버(지금 서버) ──(127.0.0.1:4748, 내부 전용)── 파이썬 RAG 서버(rag/)
                                   │ spacelog.db, vault/                        │ <데이터 폴더>/rag/index.json
```

- **Node 서버가 유일한 진입점이다.** 브라우저는 지금처럼 4747만 쓴다. 대화 · 메시지 · 설정 · 색인 상태는 Node의 SQLite에 둔다. 별이 바뀌면 Node가 파이썬에 알린다.
- **파이썬 RAG 서버**(`rag/` 폴더): 수업의 `rag.py` 구조(읽기 → 자르기 → 숫자 → 찾기 → 답)를 따른다. Flask, `langchain-openai`의 `OpenAIEmbeddings` · `ChatOpenAI`(temperature 0), `langchain-text-splitters`의 `RecursiveCharacterTextSplitter`, `langchain-core`의 `InMemoryVectorStore`를 쓰고 `dump`/`load`로 `<데이터 폴더>/rag/index.json`에 저장한다(수업과 같은 방식). DB는 직접 읽지 않는다: 색인할 별의 내용과 첨부 파일 경로는 Node가 보내 준다.
- **파이썬 서버는 Node가 띄운다.** `npm run dev` · `npm start` 한 번이면 Node가 파이썬을 자식 프로세스로 켜고, Node가 꺼지면 같이 꺼진다. 파이썬 서버는 `127.0.0.1`에만 열고, Node가 켤 때마다 만든 비밀 토큰이 없는 요청은 거절한다.
- **파이썬이 없거나 실패해도** spaceLog는 그대로 동작한다. 챗봇 창만 "챗봇을 준비하지 못했어요"와 원인(파이썬 없음 · 설치 안 됨 · 키 없음)을 보여 준다.
- **설치**: 파이썬 3.11 이상. `npm run rag:setup`이 `rag/.venv`를 만들고 `rag/requirements.txt`를 설치한다(수업 패키지 + 파일 읽기용 `pypdf`, `python-docx`, `openpyxl`, `python-pptx`). README에 순서를 적는다.
- **키와 모델**: 프로젝트 루트의 `.env`(git에 올리지 않는다): `OPENAI_API_KEY`, `OPENAI_MODEL`, `OPENAI_EMBED_MODEL`(기본 `text-embedding-3-small`). 수업과 같은 이름이다. 화면에서 키를 입력받지 않는다(결정).
- 나중의 Docker를 위해 파이썬 쪽 설정은 모두 환경 변수(`SPACELOG_DATA`, 포트, 토큰)로 받는다(내 판단).

## 4. 색인 (자르기 · 숫자로 바꾸기)

**무엇을 읽나(결정)**

| 종류 | 읽는 것 |
|---|---|
| 별 | 제목, 글, 메모, 행성 이름 |
| 링크 첨부 | 링크 제목, 주소 |
| txt · md · csv · json · log | 본문 |
| PDF(글자 있는 것) · docx · xlsx · pptx · hwpx | 본문(xlsx는 시트별로 행을 글로, pptx는 슬라이드별로) |
| 이미지 · 스캔 PDF · hwp · 영상 · 음악 · 압축 · 그 밖 | 파일 이름만 |

- 파일 하나에서 뽑는 글은 최대 200,000자(내 판단). 넘는 부분은 버리고 상태에 "일부만 읽음"을 남긴다.
- **조각**: `RecursiveCharacterTextSplitter`, 크기 800자 · 겹침 100으로 시작한다(내 판단, 실제 확인에서 이상하면 고친다). 조각마다 메타데이터: `star_id`, `planet_id`, `created_at`, `source`(`body` · `memo` · `title` · 첨부 id), `file_name`, `kind`.
- 조각 id는 `<별 id>:<순번>`이다. 별 하나를 다시 색인할 때는 그 별의 조각을 모두 지우고 새로 넣는다.
- `index.json`은 바뀔 때마다 쓰지 않고 모아서 쓴다: 마지막 변경 뒤 5초, 또는 처음부터 다시 읽기 중에는 별 50개마다, 그리고 서버를 끌 때. 임시 파일에 쓴 뒤 바꿔 달아 반쪽 파일이 남지 않게 한다(내 판단). 파이썬이 갑자기 꺼져 마지막 몇 개를 잃어도, 켤 때 Node가 해시를 비교해 다시 보내므로 맞춰진다.
- **자동 맞추기**: Node는 별을 만들기 · 메모 · 제목 바꾸기 · 행성 옮기기 · 지우기, 행성 이름 바꾸기 · 합치기 · 지우기, 첨부 변경이 있을 때 그 별(들)을 "다시 색인할 것"으로 표시하고 하나씩 파이썬에 보낸다. 실패하면 상태에 원인을 남기고 1분 · 5분 · 30분 뒤 다시 시도한다.
- **상태 표**(Node DB, 새 표 `rag_status`): `star_id`, `content_hash`(색인에 들어간 내용의 해시), `status`(`pending` · `done` · `failed` · `skipped`), `error`, `indexed_at`. 서버를 켤 때와 챗봇을 켤 때 모든 별을 비교해, 없거나 해시가 다르거나 실패한 별을 다시 보낸다(처음 켤 때 전부 읽는 것도 이것으로 된다).
- **빼 둔 행성**: 그 행성의 별은 색인하지 않고(`skipped`), 이미 있던 조각은 지운다. 검색할 때도 한 번 더 걸러 낸다(두 겹).
- **챗봇을 끄면** 색인 작업과 OpenAI 요청을 모두 멈춘다. 색인 파일은 지우지 않는다.

## 5. 질문에 답하기 (찾기 · 답하기)

1. **질문 풀기**: 질문, 지금 화면 맥락(열린 행성 · 별), 오늘 날짜, 같은 대화의 앞 내용 일부를 주고 모델에게 JSON으로 받는다: `intent`(`find` · `ask` · `summarize` · `chat`), 기간(`from` · `to`), 행성, 대상 별, 검색어. 날짜 · id는 코드가 검사하고 틀리면 버린다.
2. **찾기 · 묻기**: 검색어로 조각을 찾되 기간 · 행성 · 빼 둔 행성 조건으로 거른다. 점수가 기준보다 낮은 조각은 버린다. 남은 조각이 없으면 **모델을 부르지 않고** "기록에서 찾지 못했어요"를 돌려준다.
   - `find`: 조각이 나온 별들을 출처 카드로 보여 주고, 한두 문장 안내만 만든다.
   - `ask`: 수업의 답 프롬프트(찾은 조각만 보고 답한다, 없으면 모른다고 한다, 한국어 해요체)로 답한다.
3. **요약**: 검색이 아니라 **걸러서 모으기**다. 대상(별 하나 · 행성 · 기간)의 조각을 모두 모아, 한 번에 넣을 수 있으면 한 번에, 많으면 묶음별로 요약한 뒤 합친다. 대상 별이 200개를 넘으면 "범위가 너무 넓어요. 기간이나 행성을 좁혀 주세요"라고 하고 멈춘다(내 판단).
4. **출처는 코드가 붙인다(내 판단).** `ask` · `summarize`: 모델에게 조각을 번호 붙여 주고, 답 끝에 실제로 쓴 번호 목록을 정해진 형식으로 내게 한다. 코드는 그 번호가 실제로 준 조각인지 검사하고, 맞는 것만 별 카드로 만든다(번호 목록은 화면에 보이지 않는다). 쓴 번호가 하나도 없으면 "기록에서 찾지 못했어요"로 바꾼다. `find`: 찾은 조각의 별이 곧 결과라 카드로 그대로 보여 준다. 모델이 출처를 지어낼 수 없다.
5. **답은 Node 서버의 작업으로 만든다(내 판단).** 질문을 보내면 Node가 답 메시지를 `status: running`으로 만들고, 파이썬에서 흘러오는 글자를 받아 메시지에 이어 붙이며 저장한다. 브라우저는 그 메시지를 구독해 글자가 차례로 나타나게 보여 준다. 그래서 창을 닫거나, 다른 대화를 보거나, 새로고침해도 답은 계속 만들어지고, 돌아오면 이어서 보이거나 다 된 답이 보인다. 한 번에 하나의 답만 만든다(만드는 중에 다른 대화에서 보내면 "앞의 답을 만드는 중이에요"). **멈추기**는 그 작업을 끝내고 그때까지의 글을 `stopped`로 저장한다. Node 서버가 꺼지면 만들던 답은 다음에 켤 때 `failed`("답을 끝내지 못했어요")로 바뀐다.
6. `chat`(인사 · 사용법 질문)은 기록을 찾지 않고 짧게 답한다. spaceLog 사용법은 미리 써 둔 짧은 안내를 근거로 한다.

## 6. 대화 저장

- 새 표 `conversations`(`id`, `title`, `created_at`, `updated_at`, `unread`), `messages`(`id`, `conversation_id`, `role`(`user` · `assistant`), `content`, `sources`(JSON: 별 id 목록과 각 별의 파일 이름), `status`(`done` · `stopped` · `failed`), `created_at`).
- 대화 제목은 첫 질문의 앞 30자다(결정: 이름 바꾸기 없음).
- 이어 묻기: 같은 대화의 마지막 6개 메시지를 질문 풀기 단계에 준다(내 판단).
- 대화 하나 지우기만 있다. 출처 카드가 가리키는 별이 그사이 지워졌으면 카드가 "지워진 별"로 흐리게 보인다.
- 메시지 `status`에 `running`을 더한다.
- **읽지 않음(빨간 점)**: 답이 다 만들어졌을 때 챗봇 창이 닫혀 있거나 그 대화를 보고 있지 않으면 `unread`를 켠다. 버튼 · "대화" 탭 · 목록 항목에 빨간 점.

## 7. 화면

**떠 있는 버튼(결정).** 화면 오른쪽 아래 맨 구석. 기록하기 버튼은 그 왼쪽으로 옮겨 나란히 둔다. 메인 홈과 우주 화면 모두에 있다. 그림은 **툰 스타일 원자 모양**: 보라 바탕 원, 두꺼운 잉크 테두리, 가운데 노란 별, 흰 궤도 세 줄(결정: 참고 그림의 모양을 DESIGN.md 규칙대로). 궤도가 천천히 돈다(모션 줄이기에서는 멈춤). 열리면 ✕로 바뀐다. 읽지 않은 답이 있으면 오른쪽 위에 빨간 점.

**챗봇 창.** 버튼 위로 열리는 카드, 폭 380px, 높이 최대 화면의 75%. 760px 이하에서는 화면 전체를 덮는다. 행성 패널(W-02)과 겹치면 나중에 연 것이 위에 온다. 확인 창 · 저장 창 · 꾸미기 창보다는 아래다. 아래 탭 세 개(결정):

| 탭 | 내용 |
|---|---|
| 홈 | 인사말, 바로 누르는 질문 버튼 3개("오늘 띄운 별 요약해 줘", "이번 주 기록 정리해 줘", 행성 패널이 열려 있으면 "'OO' 행성 요약해 줘"), 최근 대화 3개 |
| 대화 | 지난 대화 목록(제목 · 마지막 시각 · 빨간 점 · 지우기), 아래 "새 대화" 버튼 |
| 설정 | 챗봇 켜기 · 끄기, 빼 둘 행성 고르기, 키 상태("연결됨" · "없음"), 색인 상태 한 줄과 작은 버튼(아래), 이번 달 요청 수, OpenAI 안내 |

**대화 화면.** 위에 ← (목록으로)와 대화 제목. 말풍선 목록. 답 말풍선 아래에 출처 카드(행성 색 점 · 별 제목 · 날짜 · 찾은 파일 이름)와 "별로 저장" 버튼. 입력칸: Enter로 보내기(한글 조합 중에는 보내지 않는다), Shift+Enter 줄바꿈, 답이 나오는 동안 보내기 버튼이 "멈추기"로 바뀐다.

**출처 카드를 누르면** 우주 화면에서는 그 별로 날아가 상세를 연다(손님 별 규칙 그대로). 메인 홈에서는 블랙홀을 지나 우주로 들어간 뒤 날아간다. 챗봇 창은 열린 채로 둔다(좁은 화면에서는 닫는다).

**"별로 저장"**: 기록하기 창을 연다. 글 칸에 그 답 내용, 제목 칸은 비워 둔다. 쓰던 글이 있으면 덮어쓰지 않는다(지금 규칙 그대로).

**색인 상태 한 줄(결정)**: "챗봇이 읽은 기록: 별 132개 중 130개 · 마지막으로 읽은 시각 오후 3:20". 실패가 있으면 "읽지 못한 별 2개 [다시 시도]", 늘 작은 "[처음부터 다시 읽기]". 읽는 중이면 "읽는 중… 45 / 132".

**처음 켤 때 확인(결정, 행성 고르기는 내 판단)**: "챗봇을 켜면 질문에 필요한 기록 내용이 OpenAI로 보내져요." 그 아래에 행성 목록(체크하면 챗봇이 읽지 않는다)을 두고, 취소 · 켜기. **색인은 켜기를 누른 뒤에만 시작하므로 빼 둔 행성의 내용은 한 번도 나가지 않는다.** 켜기 전에는 챗봇 창에서 이 안내와 켜기 버튼만 보인다. 나중에 설정에서 행성을 빼면 그 행성의 조각을 바로 지운다.

**문구 바꾸기**: DESIGN.md 원칙 4와 README의 "밖으로 나가는 요청은 링크 제목뿐"을 "파일과 기록은 내 PC에 있고, 챗봇을 켜면 질문에 필요한 내용과 색인할 내용만 OpenAI로 보내져요"로 바꾼다.

## 8. 확인 방법 (결정: 평가표는 하지 않는다)

실습용이라 수업의 평가표(채점)는 만들지 않는다. 대신:
- **자동 테스트**: 파이썬은 가짜 임베딩 · 가짜 모델(LangChain의 Fake 계열)로 글 뽑기, 자르기, 거르기, 출처 번호 검사, "찾지 못했어요" 경로, 요약 묶기를 확인한다. Node는 가짜 파이썬 서버로 색인 맞추기, 대화 · 메시지 작업, 멈추기, 빼 둔 행성을 확인한다. OpenAI를 부르지 않는다.
- **실제 확인**: 마지막 단계에서 실제 키로 찾기 · 묻기 · 요약 · 없는 질문을 몇 개 직접 해 본다.
- 조각 크기 · 점수 기준은 기본값(800자 · 겹침 100, 점수 기준은 만드는 사람이 정함)으로 시작하고, 실제 확인에서 이상하면 고친다.
