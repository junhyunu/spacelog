# spaceLog 1차 구현 설계

- 날짜: 2026-11-12
- 기준 문서: [DESIGN.md](../../../DESIGN.md) v0.5, 시안 [spacelog-prototype.html](../../../spacelog-prototype.html)
- 표기: **(결정)** 은 사용자가 정한 것, **(내 판단)** 은 설계자가 정한 기본값이다. 내 판단은 사용자가 바꿀 수 있다.

## 1. 무엇을, 왜

spaceLog는 기록(글·링크·파일·이미지)을 "별"로, 카테고리를 "행성"으로 보여 주는 개인용 우주 아카이브다. DESIGN.md는 보기 전용 로컬 웹과 별도의 "수집 앱"을 전제로 쓰였다. 이번 구현은 그 둘을 **웹 하나로 합친다**(결정). 우주 화면에 파일을 끌어다 놓거나 "기록하기" 버튼을 눌러 바로 별을 띄운다.

- 개인 프로젝트다(결정). DESIGN.md의 개발 A/B/C 역할 분담은 무시한다.
- 1차가 끝나면 2차로 OpenAI API 챗봇을 붙인다(결정). 2차는 이 문서의 범위가 아니다.

## 2. 목표 · 하지 않는 것 · 실패 기준

**목표**
1. 메인 홈(W-00)에서 블랙홀 전환을 거쳐 우주(W-01)로 들어가는 흐름을 시안 그대로 가져간다(결정).
2. 우주 화면에 파일을 끌어다 놓으면 저장 창이 뜨고, 행성과 메모를 정해 저장하면 별이 생긴다(결정).
3. "기록하기" 버튼으로도 글 · 링크 · **파일 업로드**를 모두 할 수 있다(결정).
4. DESIGN.md의 W-00 ~ W-03이 실제 데이터로 동작한다. 새로고침하거나 서버를 껐다 켜도 기록이 남는다.

**하지 않는 것 (1차)**
- 챗봇, 로그인, 여러 기기 동기화, 모바일 전용 화면
- **탐사선(W-04) 전체**(결정). 탐사선 창, 탐사선 버튼, 별 목록의 체크박스, "탐사선에 싣기" 버튼, 체크한 별의 핑크 표시를 모두 만들지 않는다. 별을 골라 AI에 넘기는 일은 2차 챗봇에서 다시 다룬다.
- 폴더 통째로 끌어다 놓기, 원본 파일 편집, 파일 내용 본문 추출(PDF 글자 읽기 등)

**이러면 실패**
- 저장한 기록이나 파일이 사라진다.
- DESIGN.md의 토큰 · 컴포넌트 · 문구 규칙에서 벗어난 화면이 나온다.
- 비행 조작 없이는 못 하는 일이 생긴다(원칙 3).

## 3. 기술 구성 (내 판단, 사용자가 "제안대로" 승인)

| 부분 | 선택 |
|---|---|
| 서버 | Node.js 20 이상 + Fastify. `127.0.0.1`에만 연다. 기본 포트 4747 |
| DB | SQLite (`better-sqlite3`) |
| 파일 보관 | 사용자 홈의 `spaceLog/` 폴더: `spacelog.db`, `vault/`(파일 사본), `thumbs/`(이미지 축소본). 환경 변수 `SPACELOG_DATA`로 바꿀 수 있다 |
| 프런트 | Vite + 순수 JS 모듈 + three.js r128. 시안의 3D · 스타일 · 아이콘 코드를 옮겨 쓴다. 프레임워크는 쓰지 않는다 |
| 정적 자산 | 서체 woff2 3종, three.js를 프로젝트에 넣고 CDN을 쓰지 않는다 |
| 이미지 축소본 | 서버에서 `sharp`로 만든다(긴 변 320px) |
| 테스트 | 서버 API는 Vitest로 검증한다. 화면은 브라우저에서 DESIGN.md 11장 목록으로 확인한다 |
| 실행 | `npm run dev`(개발), `npm run build` 뒤 `npm start`(서버가 화면까지 함께 제공) |

폴더 구조는 `server/`(API, DB, 보관함)와 `web/`(화면)로 나눈다. 세부는 만드는 사람이 정한다.

## 4. 데이터

DESIGN.md 7장의 필드를 따른다. 더하는 것만 적는다.

**행성** `planets`: id, name(최대 20자), description, color_index(1~16), deco(10종), ring(0 · 1), slot(3D 자리), created_at. 색 · 장식 · 고리는 6-6 참고

**별** `stars`: id, type(text · image · link · file), title, body, url, link_title, file_name, file_ext, file_size, file_hash(SHA-256), vault_path, thumb_path, memo, planet_id, created_at(넣은 시각), search_text

- **행성 자리**(내 판단): 행성 수에 상한을 두지 않는다. 처음 10개는 시안의 자리(예시 행성 4곳, 그다음 빈 자리 6곳)를 순서대로 쓴다. 11번째부터는 그 바깥을 도는 고리 위에 고르게 놓고, 고리가 차면 더 큰 고리를 만든다. 합치기 · 삭제로 빈 자리는 다음 새 행성이 먼저 쓴다. 조망 카메라 거리는 62를 기본으로 하되, 모든 행성이 화면에 들어오도록 필요한 만큼 늘린다(원칙 1).
- **행성 설명**(내 판단): 새 행성은 설명이 비어 있고, 비어 있으면 이름표 둘째 줄을 그리지 않는다. 이름 · 설명 · 색 · 장식 · 고리는 행성 꾸미기 창(6-6)에서 바꾼다. 시안의 "새로 만든 행성" 고정 문구는 쓰지 않는다.
- `search_text`는 제목 · 본문 · 메모 · 링크 제목 · 파일 이름을 합친 글이다. 1차에서는 쓰지 않고 2차 챗봇을 위해 채워만 둔다(내 판단).
- 처음 실행하면 행성이 0개다. 예시 데이터는 넣지 않는다(내 판단).

## 5. API

DESIGN.md 7장 "로컬 서버에 필요한 요청"을 그대로 만든다. 더하는 것:

| 요청 | 내용 |
|---|---|
| 별 만들기(글 · 링크) | JSON: type, title, body 또는 url, planet_id, memo |
| 별 만들기(파일) | multipart: 파일 1개 이상 + planet_id, memo, (파일별 title). 파일마다 별 1개 |
| 파일 내려받기 · 축소본 | 보관함 사본과 축소본을 화면에 준다 |

규칙
- **파일 종류**: 이미지 MIME(png, jpg, gif, webp 등)이면 `image`, 나머지는 `file`.
- **크기 상한**: 파일 하나에 500MB. 넘으면 저장하지 않고 "500MB보다 큰 파일은 담을 수 없어요"(내 판단).
- **같은 파일**: 해시가 같은 별이 이미 있으면 저장하지 않고 "이미 있는 별이에요"(내 판단).
- **링크 제목**: 저장할 때 서버가 그 주소를 한 번 열어 `<title>`을 가져온다. 3초 안에 못 가져오면 주소를 제목으로 쓴다. 이것이 1차에서 유일하게 밖으로 나가는 요청이다(내 판단).
- **원본 열기 · 폴더에서 보기**: 브라우저는 끌어다 놓은 파일의 원래 위치를 알려 주지 않는다. 그래서 둘 다 **보관함 사본**을 대상으로 한다. 원본 열기는 OS 기본 프로그램으로 사본을 열고, 폴더에서 보기는 탐색기에서 사본을 선택해 보여 준다. 링크는 브라우저 새 탭으로 연다.
- **사본이 없는 별**: 글 별은 원본 열기 · 폴더에서 보기를 둘 다 숨긴다. 링크 별은 원본 열기(새 탭)만 두고 폴더에서 보기를 숨긴다(내 판단).
- **실행 파일은 열지 않는다**: 확장자가 exe · bat · cmd · com · msi · lnk · ps1 · vbs · js · scr 등 실행되는 종류면 "원본 열기"가 폴더에서 보기와 같게 동작한다(내 판단). 열기 요청은 별 id만 받고 경로를 받지 않는다. 서버는 Host · Origin이 자기 주소가 아닌 요청을 거절한다.
- **별 삭제**: DB 기록, 보관함 사본, 축소본을 함께 지운다.
- **행성 합치기**: 별을 대상 행성으로 옮기고 원래 행성을 지운다.
- **행성 삭제**(결정): 별이 있는 행성도 지울 수 있다. 별이 있으면 "별도 함께 지우기"(별의 기록 · 사본 · 축소본까지 삭제) 또는 "다른 행성으로 옮기고 지우기" 중 하나를 골라야 한다. 6-7 참고.

### 6-3. 끌어다 놓기 (새로 추가)

- W-00과 W-01 어디서나 받는다(내 판단). 저장 창이나 확인 창이 열려 있을 때는 받지 않는다.
- 파일을 화면 위로 가져오면 화면 전체에 잉크색 반투명 막 + 가운데 점선 카드 "여기에 놓으면 별이 돼요"가 뜬다. 화면 밖으로 나가면 사라진다.
- 놓으면 저장 창이 "파일" 탭으로, 놓은 파일이 담긴 채 열린다.
- 붙여넣기(Ctrl+V)도 받는다. 입력창에 포커스가 없을 때만. 파일 · 이미지면 "파일" 탭, 주소 하나면 "링크" 탭, 그 밖의 글이면 "글" 탭으로 내용이 담긴 채 열린다.
- 쌓임 순서: 놓기 막은 42(저장 창 43과 확인 창 45보다 아래).

### 6-4. W-05 저장 창 "별 띄우기" (새로 추가)

가운데 모달. 최대 520px × 80vh. DESIGN.md의 카드 · 입력창 · 버튼 컴포넌트를 쓴다. 쌓임 순서 43.

| 영역 | 요소 |
|---|---|
| 머리 | 제목 "별 띄우기"(display 20px), 종류 탭(알약 3개): 글 / 링크 / 파일, ✕ |
| 내용 | 탭에 따라 아래 표 |
| 제목 | 한 줄 입력. 자동으로 채워지고 고칠 수 있다 |
| 행성 | 선택 상자(색 점 + 이름). 맨 아래 항목 "+ 새 행성 만들기"를 고르면 바로 아래에 이름 입력칸(최대 20자)이 나온다 |
| 메모 | 3줄 입력, 비워도 된다 |
| 발 | 고스트 "취소", 노랑 "별 띄우기" |

| 탭 | 내용 영역 | 제목 자동 채움 |
|---|---|---|
| 글 | 여러 줄 입력(6줄) | 본문 첫 줄(최대 40자) |
| 링크 | 주소 입력 한 줄(mono) | 비워 두면 서버가 가져온 링크 제목 |
| 파일 | 점선 상자 "파일을 여기에 놓거나" + 고스트 "파일 고르기". 담긴 파일은 목록(썸네일 · 이름 · 크기 · ✕)으로 보인다. 여러 개 담을 수 있다 | 파일 이름(확장자 뺀 것). 파일이 2개 이상이면 제목 칸을 숨기고 목록에서 파일별로 쓴다 |

동작
- 파일이 여러 개면 **파일마다 별 1개**가 생긴다. 행성과 메모는 모두 같게 들어간다.
- 행성 기본값: 행성 패널(W-02)이 열려 있으면 그 행성, 아니면 마지막으로 저장한 행성, 그것도 없으면 "+ 새 행성 만들기"가 골라진 상태.
- "별 띄우기"가 비활성인 때: 내용이 비었거나(글 없음 · 주소 없음 · 파일 없음) 행성이 정해지지 않았을 때.
- 주소는 `http://` 또는 `https://`로 시작해야 한다. 아니면 입력칸 아래에 "주소는 http로 시작해야 해요".
- 저장 중에는 버튼이 "띄우는 중…"으로 바뀌고 비활성이 된다. 큰 파일은 진행률(%)을 버튼에 보인다.
- 성공하면 창이 닫히고 토스트 "별 N개를 띄웠어요". W-01이면 새 별이 화면 가운데 아래에서 솟아 그 행성 궤도로 들어간다(DESIGN.md 9-3 "별이 옮겨감" 곡선). 행성은 커지고, 패널이 열려 있으면 새 항목이 1.2초 핑크로 보인다. W-00이면 인사말 숫자와 카드가 새로 고쳐진다.
- 일부만 성공하면(같은 파일, 크기 초과) 성공한 것만 저장하고 토스트 "별 N개를 띄웠어요. M개는 이미 있거나 너무 커서 빼놨어요".
- 서버 오류면 창을 닫지 않고 발 위에 "저장하지 못했어요. 다시 눌러 주세요". 입력한 내용은 그대로 둔다.
- Esc · 바깥 클릭 = 취소. 내용을 입력한 뒤라면 확인 창 "쓰던 기록을 버릴까요?"를 띄운다.
- 창이 열려 있는 동안 비행 키는 받지 않는다. Esc 순서는 확인 창 → 저장 창 → 전환 건너뛰기 → W-03에서 목록 → 패널 닫기이다.

**장식 10가지.** 모두 시안의 장식과 같은 방식(표면에 작은 로우폴리 조각을 12~18개 흩뿌림, 잉크 외곽선, 3단 음영)으로 만든다. 색은 행성 색의 어두운 톤 · 밝은 톤과 흰색 · 포인트 색 하나를 쓴다.

| id | 이름 | 조각 모양 |
|---|---|---|
| town | 마을 | 시안 그대로 |
| crystal | 수정 | 시안 그대로 |

**고리**: 있음 / 없음. 시안의 고리 그대로.

**자동 배정**: 지금까지 만든 행성 수를 n(0부터)이라 하면 색은 `n % 16 + 1`, 장식은 위 표의 `n % 10`번째, 고리는 `n % 3 === 1`일 때 있음. 이렇게 하면 80개까지 같은 색 · 장식 짝이 다시 나오지 않는다.

**행성 꾸미기 창**: 가운데 모달(최대 440px, 쌓임 순서 44). 새 행성을 만들 때와 이미 있는 행성을 고칠 때 같은 창을 쓴다.

### 6-7. 행성 삭제 (결정)

W-02 메뉴 항목은 "새 행성 만들기 / 행성 꾸미기 / 다른 행성과 합치기 / 행성 삭제" 네 개다. DESIGN.md의 "빈 행성 삭제"와 "별이 있으면 못 지워요"는 쓰지 않는다.

| 경우 | 확인 창 |
|---|---|
| 별 0개 | 제목 "행성 'OO'을(를) 지울까요?", 설명 "되돌릴 수 없어요.", 취소 + 핑크 "지우기" |
| 별 있음 · 다른 행성 있음 | 제목 같음. 고르기 2개(라디오): "별 N개를 다른 행성으로 옮기고 지우기"(기본 선택, 아래에 행성 선택 상자) / "별 N개도 함께 지우기"(고르면 설명 "별 N개의 기록과 보관함 복사본이 함께 지워져요. 되돌릴 수 없어요."). 취소 + 핑크 "지우기" |
| 별 있음 · 행성이 이것 하나뿐 | 제목 같음. 설명 "별 N개의 기록과 보관함 복사본이 함께 지워져요. 되돌릴 수 없어요." 취소 + 핑크 "지우기" |

- N은 기간과 상관없이 그 행성의 전체 별 개수다.
- 지운 뒤 패널을 닫고 조망으로 돌아가며 토스트 "행성 'OO'을(를) 지웠어요" 또는 "별 N개를 'XX'(으)로 옮기고 지웠어요".

### 6-9. 한 창에서 기록하기 · 별 하나에 여러 첨부 (2026-11-12 · 결정)

1차를 써 본 뒤 사용자가 정했다. 6-4(W-05 저장 창)의 글 / 링크 / 파일 탭을 없애고 한 창에서 쓴다. **글 + 첨부 파일 + 링크를 저장하면 별 하나가 된다**(사용자 결정: 첨부마다 별을 따로 만들지 않는다).

**데이터.**
- 별(`stars`)은 제목 · 본문(`body`) · 메모 · 행성 · 넣은 시각을 가진다. 첨부는 새 표 `attachments`에 둔다: id, star_id, kind(`image` · `file` · `link`), position(순서), file_name, file_ext, file_size, file_hash, vault_path, thumb_path, url, link_title, created_at.
- 별의 `type`은 남기되 계산한 값이다: 첨부가 없으면 `text`, 있으면 첫 첨부의 kind. 목록 썸네일 · 아이콘은 이 값과 "첫 이미지 첨부"로 정한다.
- 기존 데이터는 서버가 켜질 때 한 번 옮긴다(파일 · 이미지 · 링크 별 → 첨부 1개짜리 별). 옮기기 전에 `spacelog.db`를 `spacelog.db.bak-1`로 복사해 둔다. 옮긴 뒤에도 보관함 파일 경로는 바뀌지 않는다.
- `search_text`는 제목 · 본문 · 메모 · 첨부 파일 이름 · 링크 주소 · 링크 제목을 합친다.

**규칙.**
- 별 하나에 첨부는 50개까지. 파일 하나 500MB 상한, 같은 파일(해시) 중복 금지, 0바이트 파일 허용은 그대로 첨부 단위로 적용한다.
- 같은 별 안에서 같은 파일을 두 번 넣으면 하나만 남긴다. 다른 별에 이미 있는 파일이면 그 첨부만 빼고 저장하고 알린다("이미 있는 파일 N개는 빼고 띄웠어요"). 뺀 뒤 남는 것이 없으면(본문도 없으면) 별을 만들지 않고 "이미 있는 별이에요".
- 링크는 http · https만. 링크마다 서버가 제목을 가져온다(링크당 3초, 동시에).
- 제목을 비우면: 본문 첫 줄(40자) → 없으면 첫 파일 이름(확장자 뺌) → 없으면 첫 링크 제목 · 주소.
- 별을 지우면 첨부의 보관함 사본 · 축소본도 모두 지운다.
- 원본 열기 · 폴더에서 보기는 첨부 단위로 한다(5장 규칙 그대로).

**기록하기 창(W-05 대체).**

| 영역 | 요소 |
|---|---|
| 머리 | "별 띄우기", ✕ |
| 글 칸 | 큰 입력칸(6줄, 늘어남), placeholder "무엇이든 남겨 보세요" |
| 도구 줄 | 글 칸 바로 아래 아이콘 버튼 2개: 파일 첨부(Lucide `paperclip`, "파일 첨부"), 링크 붙이기(Lucide `link`, "링크 붙이기") |
| 첨부 목록 | 칩 목록. 파일 칩: 썸네일(이미지) 또는 아이콘 · 이름 · 크기 · ✕. 링크 칩: 링크 아이콘 · 주소 · ✕ |
| 제목 | 한 줄, 비워도 됨(자동 제목 규칙을 placeholder로 보여 준다) |
| 행성 | 지금과 같다(+ 새 행성 만들기 포함) |
| 발 | 취소 · 별 띄우기 |

- 링크 붙이기를 누르면 도구 줄 아래에 주소 입력 한 줄과 "붙이기" 버튼이 나온다. Enter(한글 조합 중이 아닐 때) 또는 "붙이기"로 칩이 된다. http · https가 아니면 "주소는 http로 시작해야 해요".
- 글 칸에 주소만 하나 붙여넣으면 링크 칩으로 바꿀지 묻지 않고 글로 둔다(사용자가 원하면 링크 붙이기를 쓴다). 화면 어디든 주소를 끌어다 놓거나, 글 칸 밖에서 붙여넣은 주소 하나는 링크 칩이 된다.
- 파일을 끌어다 놓거나 붙여넣으면 첨부 칩으로 들어간다(창이 닫혀 있으면 창을 연다). 쓰던 글은 그대로 둔다.
- "별 띄우기"는 글 · 첨부 중 하나라도 있고 행성이 정해졌을 때 활성. 메모 칸은 창에서 없앤다(별 상세에서 쓴다).
- 저장은 요청 하나(multipart)로 한다. 진행률, 멈추기, 실패 시 내용 유지, 새 행성 재사용 규칙은 지금과 같다.

**별 상세(W-03).**
- 머리 · 정보 · 메모 · 행성 옮기기 · 지우기는 그대로.
- 본문이 있으면 본문(점선 상자). 그 아래 첨부 목록: 이미지는 축소본 격자(누르면 크게 보기), 파일은 아이콘 · 이름 · "PDF · 1.2MB" · 원본 열기 · 폴더에서 보기, 링크는 제목 · 주소 · 원본 열기.
- 지우기 확인 문구: 첨부 파일이 있으면 "기록과 첨부 파일 N개의 보관함 복사본이 함께 지워져요. 되돌릴 수 없어요.", 없으면 "기록이 지워져요. 되돌릴 수 없어요."

**목록 · 3D.** 행성 패널 목록의 썸네일은 첫 이미지 첨부의 축소본, 없으면 type 아이콘. 첨부가 2개 이상이면 제목 옆에 작은 클립 아이콘과 개수. 3D 별은 지금처럼 별 하나다.
